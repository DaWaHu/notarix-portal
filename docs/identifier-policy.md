# Notarix Signings Identifier Policy

This policy defines permanent operating identifiers for approved clients,
approved notaries, and orders. The identifiers must be generated by the
database-backed workflow at the moment the record becomes permanent. They must
not be reserved, promised, or reused before final approval or order creation.

## Identifier Structure

Permanent record identifiers use this structure:

```text
PREFIX-STATE-YYMM-SEQUENCE
```

Where:

- `PREFIX` identifies the record family.
- `STATE` is the two-letter state or jurisdiction code tied to the record.
- `YYMM` is the two-digit year and two-digit month of activation or order creation.
- `SEQUENCE` is a four-digit database sequence for that record family.

The compact operating code omits separators and the record-family prefix:

```text
STATEYYMMSEQUENCE
```

Example:

- Display identifier: `NSC-TX-2607-1234`
- Compact client code: `TX26071234`
- Next same-state, same-month client code: `TX26071235`

## Record Families

Client profile numbers use `NSC`.

Example: `NSC-TX-2607-1234`

Notary profile numbers use `NSN`.

Example: `NSN-NC-2607-0001`

Order numbers use `ORD`.

Example: `ORD-NC-2607-0001`

## Assignment Rules

- `NSR` remains an intake request number only.
- `NSC` is assigned only after final approval of a client profile.
- `NSN` is assigned only after final approval of a notary profile.
- `ORD` is assigned when the Order Case File is created.
- The Order remains the central system record for assignment, documents,
  signers, lifecycle, completion, delivery, billing, and audit history.
- Profile and order sequences must be database-generated or transactionally
  protected so two records cannot receive the same identifier.
- Approved profile numbers are permanent and must never be reused.

## State And Date Rules

Client profile state is the business registration or primary operating state
selected during staff approval.

Notary profile state is the commission or primary authorized operating
jurisdiction selected during staff approval.

Order state is the signing or service jurisdiction for the Order Case File.

The `YYMM` segment must be based on the UTC timestamp for activation or order
creation, then displayed using Notarix Signings user-facing date and time
formatting rules elsewhere in the portal.
